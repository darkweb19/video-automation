## C2.6 separate-track retry behavior

Separate direct video and audio tracks are requested concurrently. Each track has at most two transfer attempts, with a 250 ms delay before its one local retry for request/fetch errors, HTTP 408/429/5xx responses, and interrupted or incomplete bodies/lengths. Before retrying a failed track, the importer removes its partial generated file, syncs the containing directory, and restores that track's committed bytes to the shared scratch-space reservation. This reset is track-local, so a successfully downloaded peer remains available while the failed track retries. Retryable local storage failures use the outer import retry after cleanup instead of another transfer attempt.

An HTTP 401, 403, or 410 response from a selected track does not repeat that signed URL. It schedules the existing outer import retry, which clears staged YouTube artifacts and extracts fresh metadata on the next attempt; the total import limit remains five attempts.

The added allowlisted track reason codes are `track_request_failed` (request transport/fetch failure; local retry), `track_http_retryable` (HTTP 408, 429, or 5xx; local retry), `track_access_denied` (HTTP 401, 403, or 410; outer fresh-metadata retry), `track_body_incomplete` (interrupted read or length mismatch; local retry), `track_storage_failed` (local track storage; outer retry when retryable), and `track_transfer_aborted` (a transfer stopped after its peer failed). The browser allowlist in `clipping.js` includes the same six track codes.

## Accepted input and user flow

- Require the existing explicit `rights_attested` confirmation before creating an import. This records the user's attestation; it is not proof of ownership or a decision by YouTube.
- Accept one public, watchable video from `youtube.com` / `www.youtube.com` / `m.youtube.com`, `youtube-nocookie.com` / `www.youtube-nocookie.com`, or `youtu.be`, over HTTPS on port 443. Supported paths are a standard `watch?v=...`, `/shorts/{id}`, `/embed/{id}`, and the matching one-segment `youtu.be/{id}` form. The video ID is exactly 11 ASCII letters, digits, `_`, or `-`.
- Strip nonessential query fields such as tracking/share parameters from the stored canonical reference. Reject any playlist/multi-video selector, including a `list` value, and reject live/upcoming paths and media. Do not accept channel, search, playlist, URL shortener, arbitrary host, userinfo, IP literal, non-443 port, or fragment forms.
- Do not use browser cookies, account credentials, netrc, local yt-dlp configuration, extractor plugins/options supplied by the caller, browser automation, private/unlisted access assistance, age-gate bypass, DRM bypass, or login flow. A public watch page that requires restricted access is unavailable to this importer.
- Return an actionable original-file upload fallback for missing tools, blocked/unavailable videos, restricted formats, active/upcoming streams, ambiguous original audio, unsafe track pairs, and videos without a safe direct audio/video path. Never promise that every public YouTube video can be imported.

## Extractor and network boundary

The Docker image installs yt-dlp `2026.8.19` and yt-dlp-ejs `0.8.0` from SHA-256-pinned wheels, Deno `2.7.4-r2` from Alpine v3.24's signed package index, plus FFmpeg/ffprobe and Python 3. Python is used only as a fixed launcher for the separate-track mux's kernel-enforced file-size limit; it runs in isolated mode with site initialization disabled and immediately replaces itself with FFmpeg. The Deno package's official page does not publish a whole-APK SHA-256; see the [YouTube runtime lock](../../tools/clipping/requirements-youtube.lock) for the package provenance and exact integrity evidence. Helper code is bundled; the import does not fetch runtime components dynamically.

Run yt-dlp as a bounded argument-vector subprocess, never through a shell. It ignores user configuration and plugins, uses no cookies, network credentials, netrc, or playlist, retains `--skip-download` and `--no-simulate`, and emits one JSON metadata object for the canonical URL. The fixed invocation requests full bounded `formats[]` metadata and removes the mux-only `--format` selector. Go makes the final selection from that list. Limit extractor time to 90 seconds and JSON output to 4 MiB; discard stderr and never put raw output in logs or API errors. Run Deno with a private per-import temporary cache and remove it after success, failure, timeout, or cancellation. The pinned extractor and runtime values are defined in [clipping_youtube.go](../../internal/app/clipping_youtube.go).

All extractor page, player, API, and JavaScript-challenge requests pass through an ephemeral authenticated loopback HTTPS CONNECT proxy. The proxy permits port 443 only and only these host families: `youtube.com`, `www.youtube.com`, `m.youtube.com`, `youtube-nocookie.com`, `www.youtube-nocookie.com`, `youtubei.googleapis.com`, `youtube.googleapis.com`, `jnn-pa.googleapis.com`, and subdomains of `googlevideo.com`. It rejects ordinary HTTP and all other destinations, resolves A and AAAA once for each hop, rejects a hop if any answer is not global unicast, and dials only validated addresses while preserving the requested TLS hostname. It allows at most 12 tunnels at once; proxy headers are capped at 4 KiB, the header deadline is 8 seconds, upstream dial timeout is 10 seconds, and cancellation/timeout closes all active tunnels. The exact allowlist and enforcement live in [clipping_youtube_proxy.go](../../internal/app/clipping_youtube_proxy.go) and [clipping_youtube.go](../../internal/app/clipping_youtube.go).

## Metadata and stream selection

The extractor result must identify exactly the requested video and provide a finite positive duration within the four-hour bound. Reject playlist/result objects, mismatched IDs, active/upcoming live status, unknown live-status values, unsupported metadata, and selected declared sizes above their limits. A `was_live` result is accepted only as a completed archive after its bounded duration and safe direct audio/video format validate; `post_live` remains rejected because yt-dlp may still be processing it. Treat top-level yt-dlp format selection as untrusted metadata: only eligible entries in `formats[]` drive the selection.

Selection has two ordered paths:

1. Prefer a direct HTTPS progressive MP4 with both audio and video, choosing the highest eligible MP4 by height, pixel area, width, frame rate, yt-dlp quality, then total bitrate; if none exists, choose the highest eligible progressive WebM using the same ranking. Missing or null optional numeric ranking fields count as zero. Pinned yt-dlp can emit `quality: -1` for unknown quality and `quality: -1.5` for unknown DRC quality. Since quality only ranks candidates, any finite signed value remains eligible; negative values sort below nonnegative quality when earlier criteria tie. Malformed or non-finite ranking values and negative physical metrics make that format ineligible. Metadata order breaks exact ties. MP4 takes priority over WebM even when a WebM candidate has higher resolution.
2. Only when neither progressive pool has an eligible candidate, choose the highest-ranked direct HTTPS video-only MP4/WebM stream using height, pixel area, width, frame rate, yt-dlp quality, then bitrate; metadata order breaks exact ties. Pair it with an eligible audio-only MP4/M4A/WebM stream. yt-dlp `2026.8.19` marks its source-original audio with `language_preference: 10`; that pinned metadata value selects the original when language or format-note metadata shows competing language/dub choices. `format_note: "Original"` is retained as descriptive metadata in the offline contract, but the numeric preference is the selection marker. The importer examines audio language and Original metadata across direct and manifest entries; if the known Original exists only through unsupported HLS/DASH or another ineligible format, it fails with the upload fallback instead of treating a direct alternate language as the sole choice. If only one unambiguous audio language is available, the importer can use that sole track. Within the selected original-audio set, rank by audio bitrate, sample rate, channel count, then total bitrate; metadata order breaks exact ties.

Format IDs are not selection or ranking rules. Signed URLs, format IDs, and headers remain ephemeral. Eligible video tracks must be direct HTTPS MP4/WebM formats; audio tracks may also use M4A. Candidates need the expected audio/video codec roles, an approved CDN URL, and safe bounded request headers. Separate track inputs need not use matching extensions: FFmpeg stream-copies the selected pair into a temporary Matroska file. FFmpeg and strict local ffprobe validation decide whether the codec pair is compatible. A failed mux/probe returns the original-file upload fallback; it never triggers an unannounced lower-quality video or autodub retry.

The importer preserves audio. It does not merge HLS/DASH manifests, download a video-only stream alone, select an autodub in place of an identifiable original, or re-encode the tracks. A progressive combined stream may be lower resolution than YouTube's separate adaptive formats because it is preferred when safe. If there is no supported progressive stream, the separate path uses the highest-ranked direct compatible video candidate and original audio metadata available. This is a defined selection policy, not a guarantee of source-best quality across YouTube's adaptive catalogue.

## Track transfer, mux, storage, and publication

The selected direct URL is short-lived secret data held in memory only. The Go importer fetches one URL for a progressive stream; for separate tracks, it fetches the video and audio URLs concurrently. Both use a pinned-DNS HTTP transport. Each hop is independently checked for HTTPS/443, the approved YouTube CDN family, all-public DNS answers, and a pinned socket; redirects are limited to five and validated again. TLS handshakes are limited to 10 seconds and response headers to 30 seconds. Requests never send cookies, authorization, or arbitrary extractor headers. Only a bounded printable User-Agent and, when requested, an allowed YouTube-root or exact canonical-video Referer are forwarded; the Referer is replaced with the canonical watch URL for the validated video ID.

Accept only complete HTTP 200 responses with supported media content types. Reject partial responses, `Content-Range`, unsafe redirects, unsupported content, malformed headers, declared oversize, and streamed oversize. A progressive file is limited to 20 GiB. For separate tracks, the combined downloaded video-plus-audio bytes are limited to 20 GiB even when a track has no declared size; the finished muxed source is independently limited to 20 GiB. The storage check reserves up to 20 GiB for aggregate temporary tracks plus up to 20 GiB for the final source, while retaining a 4 GiB physical free-space floor and accounting for other outstanding source reservations. The application also enforces its 100 GiB clipping storage ceiling. Do not lower these limits as a shortcut.

Separate tracks are downloaded to generated files under the source's private directory, then stream-copied by FFmpeg into a seekable Matroska file without re-encoding. FFmpeg writes to the generated temporary path so Matroska can finalize its duration and seek indexes; no duration tags are fabricated. A fixed `/usr/bin/python3 -I -S -c` launcher runs with a sanitized environment, sets `RLIMIT_FSIZE` to the exact output-byte cap, and uses `execv` to replace itself with the fixed-path FFmpeg process. The kernel rejects any write that would extend the output beyond that cap; an FFmpeg failure at the cap or file-size-limit signal is reported as an output-size failure. The whole import is limited to 12 hours; copy-mux is limited to three hours and 20 GiB of output. The app verifies temporary files remain regular files under the generated source directory and deletes track/intermediate files on failure or cancellation. It does not persist extractor-controlled filenames or titles. The source record keeps the encrypted canonical watch reference plus the permitted generated source name.

Before publication, ffprobe validates the final file's supported container, stream codecs, dimensions, frame rate, timestamps, and durations; dimensions must be 144–8192 pixels per side and at most 50 megapixels, and the app requires an installed FFmpeg decoder for each selected codec. FFprobe has a 15-second timeout, 64 KiB output cap, and 64 MiB allocation bound; the FFmpeg decoder-list query is limited to five seconds and 2 MiB of output. The selected video/audio codecs, video dimensions, and frame rate are compared with a sanitized import expectation. Video and audio stream durations, total duration, and extractor duration must agree within two seconds. Stream start timestamps must remain within two seconds of each other and within the media-duration timeline, allowing at most a two-second lead or overrun. A valid final file is SHA-256 hashed. The app persists its expected size and hash before atomically renaming it into the final source path, syncs the containing directory, and marks the source Ready only after rechecking the persisted final size/hash. Signed URLs, extractor headers, raw metadata, and format IDs are not written to SQLite, logs, dashboard payloads, or SSE.

## Cancellation, retry, and restart behavior

Cancellation closes the active HTTP requests and FFmpeg process, stops later stages, writes a durable source tombstone, then removes generated files and records cleanup completion after syncing the directory. A canceled import cannot advance to Ready, and an interrupted tombstone resumes cleanup after restart. For separate tracks, eligible individual transfer failures use the bounded local retry described above. Retryable network, proxy, lease, process, or selected-track access-denied failures that reach the outer import retry clear partial YouTube track/download data and start again from metadata extraction; the importer does not resume a track using an older signed URL. If cleanup cannot complete, the import cannot proceed until a later cleanup/retry succeeds. Imports allow at most five attempts with exponential backoff capped at five minutes; permanent format, original-audio, size, duration, or media failures clean generated files and release the source reservation after directory cleanup succeeds.

The importer persists only a sanitized selection expectation: duration, normalized video/audio codecs, selected video dimensions/frame rate, source-side quality/bitrate metadata, and whether separate tracks and yt-dlp's Original preference were used. Probe revalidation compares codecs, dimensions, frame rate, duration and timing; quality/bitrate remain selection metadata. The record contains no URL, headers, extractor output, or format ID. Import leases last 15 minutes and renew every five minutes. After process restart, the app reclaims only an expired import lease, removes stale partial tracks and mux output, resets the import expectation, and re-extracts metadata. If the final generated media file was atomically published before the Ready transaction, stored size/hash and the sanitized selection expectation are checked again as the app probes, hashes, and completes Ready publication. Conflicting, missing, or mismatched files are discarded and re-imported from fresh metadata or fail closed if cleanup cannot complete.

## Failure and operator guidance

- `runtime_unavailable`: rebuild or inspect the app image for the pinned yt-dlp, yt-dlp-ejs, Deno, FFmpeg, and ffprobe runtime; native Unix needs Python 3 with its standard `resource` module, the supported fixed tool paths, and a writable system temporary directory.
- `format_unavailable`: no supported direct progressive stream or safe compatible pair is available, or a selected stream failed strict validation. Upload an original media file you are permitted to reuse.
- `original_audio_unavailable`: the metadata does not safely identify an original track among alternatives. Upload an original media file; do not enable cookies, sign-in, autodub selection, or a wider network allowlist.
- `video_unavailable`: the public link could not be fetched without restricted access. The code does not prove whether region, provider behavior, or video restrictions caused it.
- `size_limit_exceeded` / `duration_limit_exceeded`: choose a smaller/shorter permitted original source.
- `extractor_timeout`, `extractor_exit_failure`, `extractor_proxy_failure`, and track download/mux failures identify an observed stage only. A generic extractor failure does not prove the video is private or that a format is absent; use the safe retry behavior, check configured outbound access and free storage, then use the permitted-original upload fallback if it continues.

An earlier browser trace showed a generic audio-track failure followed by `retry_scheduled`, with no successful follow-up attempt. That trace did not identify the cause. Before C2.6, selected-track HTTP 401/403 responses were permanent, so the earlier behavior does not prove signed-URL expiry. Sequential downloads exposed a plausible URL-aging risk; C2.6 requests the pair concurrently. The environment's outbound policy 403 blocked live verification, but does not identify the cause of the earlier deployed failure or establish importer behavior against a reachable source.

Source diagnostics are a bounded persistent sequence of up to 128 allowlisted stages/statuses/reason codes with a monotonic sequence. Authenticated source responses and existing live events carry recent entries so reconnects do not repeat browser logs. For safe console tracing, open developer tools **Console**, enable **Preserve log**, and filter for `[FrameVault Clipping]` before clicking **Import link**. YouTube stages include `metadata_extraction`, `format_selection`, and `media_download`; a separate-track import additionally reports `video_track_download`, `audio_track_download`, `track_mux`, `media_probe`, and `merged_validation`, followed by `media_hash` and `source_ready`. `track_mux` completes only after the seekable output is synced and staged tracks are durably removed. The console reports action/source IDs and sequence numbers with fixed stage/status labels; completed selection events use `selection=combined_tracks_selected`, `selection=separate_tracks_selected`, or `selection=original_audio_selected`, while failures use allowlisted `reason=` codes. Safe failures include `runtime_unavailable`, `extractor_proxy_failure`, `extractor_timeout`, `extractor_exit_failure`, `extractor_output_limit`, `metadata_invalid`, `format_unavailable`, `original_audio_unavailable`, `video_unavailable`, `size_limit_exceeded`, `duration_limit_exceeded`, `track_size_limit_exceeded`, `track_content_invalid`, `video_track_download_failed`, `audio_track_download_failed`, `track_mux_failed`, `track_mux_timeout`, `mux_output_size_limit_exceeded`, `av_stream_missing`, and `av_timing_mismatch`; other acquisition failures use the existing allowlisted diagnostics. Logs omit source URLs, signed URLs, format IDs, headers, extractor output, filenames, media content, and transcripts. Historical imports remain silent until a new action; logout clears browser trace tracking.

The authenticated `/api/events` stream does not set a hop-by-hop `Connection` header. Local streaming tests cover HTTP/1.1 and HTTP/2, with race checks; Go's standard HTTP/2 server also strips that header. These checks do not establish why a particular live proxy or intermediary reset a stream, and compatibility through the reported deployed path remains unverified.

An imported source does not start analysis automatically. Ready footage waits for an explicit job or batch action. After readiness, the existing browser trace reports observed analysis status and saved candidate availability; it does not invent remote worker substeps that the callback protocol does not send.

## Deterministic verification and support limits

The pinned-runtime check runs yt-dlp against synthetic local InfoJSON for both combined-stream and separate-only metadata, including original versus autodub audio fields. It checks the full `formats[]` argument/result contract and uses a deliberately inert loopback proxy address; it makes no provider request, downloads no media, and calls no model. Run it in a development environment with the pinned extractor available:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/clipping/check_youtube_runtime_contract.py
```

The script reads its fixture from a local file and points yt-dlp at an unbound loopback proxy address; it opens no network socket. The selection and acquisition regression tests use synthetic metadata and fake transports/resolvers. This C2.5 check does not test live YouTube behavior or real media. No live media or deployment check is claimed. A Docker image build was not run; that remains a separate environment/operations check.

YouTube may change page, API, player, challenge, CDN, or format behavior; access may also depend on region, availability, restrictions, codecs, and extractor support. This importer is a bounded public-link adapter with an upload fallback, not an availability or quality guarantee. Native Linux/Unix deployments must provide compatible yt-dlp at `/usr/local/bin/yt-dlp` or `/usr/bin/yt-dlp`, Deno at `/usr/bin/deno`, FFmpeg at `/usr/bin/ffmpeg` or `/usr/local/bin/ffmpeg`, ffprobe on `PATH`, `/usr/bin/python3` with the standard Unix `resource` module, and a writable system temporary directory. Native Windows source handling remains fail-closed. Imported sources may become Ready while analysis remains unavailable and related jobs stay queued. Report operational gaps instead of widening the host allowlist, enabling credentials, or claiming universal success.

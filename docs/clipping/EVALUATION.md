# AI clipping evaluation protocol

Status: preregistered proposal for C1.2; no benchmark measurements have been collected. The M1 approval authorizes this offline protocol and fixture work. It does not authorize media acquisition, provider calls, GPU jobs, or any spend. The proposed engineering ceiling is US$20 across the whole benchmark, including providers, GPU, render work, transfers, and retries. Current authorized benchmark spend remains US$0. An explicit later approval and permitted inputs are required before C1.3 starts.

The product cost target is a separate, tentative minimum of max(US$1, source duration in hours × US$1) for analysis and the initial 7–10 exports from one source. It is not measured performance, a provider quote, or permission to spend. A 15-minute source therefore has a US$1 target and a four-hour source a US$4 target. The proposal does not claim that either target or the US$20 benchmark ceiling will suffice. Stop before a stage whenever current price information and reservations indicate its allocation or the aggregate ceiling could be exceeded.

## Proposed inputs

The benchmark uses stable synthetic slot IDs below. They identify requested content, not real URLs, people, channels, rights, or benchmark results. The user must supply the actual permitted media for every slot as a file or public link and confirm reuse and benchmark processing rights. Private connected-account access is out of scope. Movie samples must be owned, licensed, or otherwise specifically permitted for this evaluation. Prefer an original source file of the indicated duration; if a 15-minute excerpt is cut from a longer source, preserve and record the original source timestamp offset. Do not discover or download corpora for these slots.

There are eight complete 15-minute samples (two hours total) and one genuine four-hour stress sample. If a requested feature is absent, record that fact and do not substitute a fabricated event. Labelers should not see pipeline identity or ranking. This compact screen is intentionally not a statistically representative language/content corpus: publish per-source counts, each language stratum, each content-type stratum, and the language-by-type cells. A cell without at least two distinct sources is descriptive only and cannot be called passed. Do not average a failed stratum into an aggregate pass. Human labeling is a separate prerequisite: the proposal assumes unpaid user/volunteer reviewers and records their hours; hiring labelers or purchasing footage is not included or authorized by the US$20 infrastructure cap.

Before any run, prepare a manifest of slot ID, exact source hash, duration, source resolution/frame rate/audio tracks, language and script mix, content type, source offset, permission confirmation, access method, and human labeler IDs. User permission is recorded in the manifest without embedding credentials or private URLs in benchmark reports. Keep the actual source bytes and access details outside these illustrative fixtures.

## Comparison and cost protocol

On the eight typical sources, compare two complete audio/video pipelines with provider choice left open until C1.3 verifies current availability, model version, licensing, language support, and price. One candidate may use a licensed open-source ASR/alignment stack on approved Modal hardware; the other may use a managed transcription option. These are experiment slots, not pinned products or recommendations. Hold candidate selection, rendering settings, input files, and human-label protocol constant; record every provider/model/version and material configuration. Run a transcript-only ablation for each selected pipeline on the same inputs. It can use speech and global transcript context but no audio-event or visual-event evidence. It is the baseline for measuring added value and source-to-export cost, not a third model recommendation.

If both complete pipelines are within the preregistered quality gates, choose the long-source winner by (1) passing gates for every adequately sampled priority language and content stratum, (2) lower all-in cost per human-usable export, then (3) lower total source-to-export cost. If one passes, it wins. If neither passes, do not run the four-hour paid stage; report the failure and required decision. A tie after exact cost rounding is resolved by a recorded user decision. Run only the selected winner on the genuine four-hour sample. Do not infer long-source quality or cost from a synthetic file.

Count all variable costs from source intake through the initial exports: provider input/output charges, GPU and worker time, CPU/render time, storage attributable to the benchmark, ingress/egress and transfer, retries, failed attempts, and any paid alignment or vision pass. Existing baseline hosting may be shown separately, but any incremental usage it incurs is included. Use the actual invoice or metered quantity multiplied by a rate with its source and effective date; do not enter guessed provider rates. One ledger row per operation records slot, pipeline/stage, operation, model/runtime version if applicable, units (USD, GPU-seconds, CPU-seconds, bytes/GiB, or attempts), quantity, unit rate, estimated reservation, actual cost, retry linkage, and evidence reference. Round display to cents but sum unrounded decimal amounts. A missing rate is unresolved cost and blocks the stage.

| Stage | Maximum allocation | Work allowed after separate C1.3 approval | Stop condition |
| --- | ---: | --- | --- |
| 0: price and input validation | US$0 | Offline only: verify supplied media hashes/permissions, current prices and licenses, dependency/runtime rates, and reservation estimates | Stop before execution if either provider rate, media rights, or full stage estimate is unknown |
| 1: paired canary | US$4.00 | Both complete pipelines and transcript-only ablations on podcast English and gaming Nepali, with render outputs and ledger entries | Stop if quality/protocol fails, unmetered cost appears, or forecast exceeds the remaining allocation |
| 2: remaining typical set | US$10.00 | Both complete pipelines and transcript-only ablations on the other six 15-minute slots | Stop on the same conditions; no automatic retry beyond the reserved attempt |
| 3: four-hour winner | US$5.00 | The selected winner only, including its initial requested exports and source-to-export accounting | Stop before queueing if estimated execution plus retry reserve exceeds this allocation |
| Unallocated reserve | US$1.00 | Only explicit retries/settlement variance, all included in the US$20 aggregate | Do not borrow from it without a new cost estimate; never exceed US$20 |

These are hard stage and aggregate ceilings, not prices or estimates. Preflight costs US$0. The US$5 long stage is above the tentative US$4 product target for the four-hour source, but both limits are separate: product-target failure is still reported and the US$5 allocation is not authority to exceed the US$20 engineering cap. The stage limits intentionally let the work stop early if current real rates cannot cover its scope. Keep an estimate/reservation ledger before each stage, then reconcile actuals immediately afterward. The total allowed amount is the lesser of the remaining stage allocation, the remaining US$20 cap, and any later user-approved limit. A failed job still consumes the cap.

## Blind labels and denominators

Two fluent human labelers independently review every source and candidate. Hide pipeline, provider, model, rank, and cost; randomize candidate presentation. Adjudicate a rubric disagreement greater than one point, transcript disagreement, word-boundary disagreement over 100 ms, or disagreement about whether a clip is usable. A third fluent adjudicator resolves disputed words and boundaries. Labelers first inspect the full source at native speed, then create a complete verbatim reference transcript with original-script text, code-switch language spans, speaker when identifiable, and manual word start/end times; they separately annotate all meaningful candidate opportunities rather than seeing suggestions first. This reduces anchoring. Keep a gold interval for each opportunity, the acceptable contiguous source-time window, language/script, content type, speech/non-speech/visual-only evidence, event description, and ratings for hook, emotional impact, retention, shareability, standalone context, and reuse/rights eligibility. Identify opportunities in the final 20% separately. Do not reward generated dialogue or a reordered sequence.

Each opportunity must have one canonical acceptable contiguous clip interval between 15 and 180 seconds. For a short event, the annotator adds the minimum meaningful setup, context, or reaction needed to reach 15 seconds; for a long event, the annotator selects the most self-contained excerpt no longer than 180 seconds. If no such contiguous interval preserves the event and context, mark it non-exportable and exclude it from selection denominators. The preferred interval and any acceptable boundary window must be recorded before pipelines run. This makes matching and boundary review reproducible.

Candidate quality is rated on five integer 1–5 editorial dimensions, with 5 strongest. A clip is human-usable only when both reviewers (or the adjudicator) rate standalone context and reuse eligibility at least 4, and the mean of the five editorial ratings is at least 4. A usable candidate must also preserve a truthful sequence and have no material cut, speech, caption, or evidence error. These ratings assess editorial suitability; they are not probabilities of virality.

Use source-time milliseconds and half-open intervals [start_ms, end_ms). Keep every denominator explicit: number of available source words, word/reference characters, aligned words, annotated opportunities, candidates returned, candidates rated, sources represented, and language/content cells. Freeze normalization as version norm-v1: normalize to Unicode NFC; remove every code point in Unicode General Category P; apply Unicode casefold only to Latin-script letters; preserve all other scripts; map each Unicode whitespace run to one ASCII space and trim it. WER tokens are the resulting whitespace-separated words. CER is edit distance over the resulting Unicode code-point sequence, including its single normalized spaces. Do not transliterate or translate before scoring. Code-switch words retain the human labeler's language spans, whose offsets are Unicode code-point positions in the unnormalized reference and hypothesis text; assign each normalized token to its center-position span, with a token crossing a span boundary labeled mixed. Compute WER as substitutions + deletions + insertions divided by reference words, with each word counted in its labeled language stratum. Record norm-v1 and the Unicode database version with every report.

For candidate-to-opportunity matching, compute temporal IoU on half-open intervals. A pair is eligible when IoU is at least 0.50 and blinded review confirms the same meaningful moment. Match one-to-one: process candidates in pipeline rank order; choose the unmatched eligible gold interval with highest IoU, breaking ties by earliest gold start then gold ID. Record matched, unmatched output, and unmatched gold counts. Precision@10 is matched usable outputs in the first ten divided by returned outputs among those ten (zero when no outputs are returned). Recall@10 is matched usable gold opportunities divided by all usable gold opportunities (N/A if none exist; exclude N/A from averages and show counts), counting gold opportunities only when within the 15–180 second export limit. Also report usable clips per source, false/duplicate clips, and all raw counts. Report macro averages by source and separately by language, content type, and language-by-type. Do not pool words or clips across sources as the only reported number.

## Preregistered gates

These thresholds are proposed acceptance targets, not observed results. Apply them independently to each adequately sampled language and content-type stratum; a stratum can pass only with at least two sources and at least 50 gold words for transcription, or 10 gold usable opportunities for selection. Below those minima report insufficient evidence, not pass. The proposed eight short slots give only two sources per type; language-by-type rows usually remain descriptive. The four-hour source adds one long gaming case, not a second source for a language/content cell.

| Measure | Gate |
| --- | --- |
| Word accuracy | WER ≤20% English, ≤25% Hindi/Hinglish, and ≤30% Nepali; additionally CER ≤15% in Hindi/Hinglish and Nepali. Report language-specific denominators and code-switch spans. |
| Word timestamps | At least 95% of spoken reference words have a non-empty aligned interval; median absolute start and end error ≤250 ms and 90th percentile ≤650 ms against manual word boundaries. A language with unsupported alignment may fail this gate even if its transcript is usable. |
| Candidate usefulness | When a source has at least seven human-usable opportunities, return 7–10 distinct usable candidates; otherwise return no more than the number of gold opportunities and explain the shortfall. Per-stratum precision@10 ≥0.70 and recall@10 ≥0.60. |
| Boundaries and validity | Every candidate is a single contiguous source excerpt, 15,000–180,000 ms, in bounds, with valid source hash/ID and evidence references. Median absolute error at each selected boundary ≤1.5 s relative to the acceptable human window. Zero generated speech, reordered dialogue, unresolved evidence references, or wrong-source timestamps. |
| Deduplication | Zero returned pairs overlap by 70% or more of the shorter interval ; initial v1 has no overlap exception. |
| Full-timeline consideration | For audio and video separately, log each actually completed source-time window [start_ms,end_ms), merge overlaps, and divide the union duration by source duration; target ≥95% measured coverage of the complete source for each modality. Planned-but-unrun windows do not count. Also include at least one completed window in each 5% source-duration bin. For outputs, if at least one usable gold opportunity occurs in the last 20%, return at least one matching candidate there. |
| Non-speech and visual evidence | If a source has an independently labeled usable non-speech or visual-only opportunity, include a matching candidate among the top ten. Across a stratum with at least ten such gold opportunities, recall of those opportunities ≥0.50. Report speech, non-speech audio, and visual-only separately. |
| Editorial ranking | Macro-averaged usable precision@10 ≥0.70 and each eligible stratum must meet its own threshold. Report each five-component editorial score alongside blinded ratings; do not interpret scores as calibrated probabilities. |
| Manual edit time | Time active human work from opening each candidate to acceptance, recording trim, caption, and crop correction separately; pause clocks during render waits. Median active edit time ≤60 seconds per usable export and p90 ≤180 seconds. Report total edit time per source and corrections per export. |
| Caption/audio synchronization | In rendered exports, at least 95% of caption cue start/end boundaries are within 300 ms of blinded human reference boundaries; median absolute error ≤150 ms. Audio and video stream start offsets differ by ≤50 ms, and output duration differs from the requested source interval by ≤100 ms. A synchronization defect is any additional audible lead/lag or truncated source speech confirmed by either reviewer. |
| Crop and caption readability | At 360×640 preview size, at least 95% of exports keep the primary speaker/action visible and captions readable to both reviewers; zero export may have clipped/overlapping caption text or text outside the configured safe area. A crop failure occurs if the primary speaker/action is obscured or out of frame for >1 continuous second. Report failures by content type and script. |
| Added value over transcript-only | Across the 15-minute set, full audio/video raises macro recall on usable non-speech and visual-only opportunities by at least 15 percentage points and yields at least one additional distinct human-usable candidate on at least four of eight sources. If no such events are present in a source, it does not count toward either denominator. |
| End-to-end cost | Include analysis through all requested initial exports, transfer, render, and retries. Report actual cost per source and per human-usable export against the transcript-only baseline. Target full-pipeline cost ≤max(US$1, duration_hours × US$1) for at least 7 of 8 short sources and ≤US$4 for the four-hour source. Any over-target case fails that source's product cost target and is reported even when the aggregate 7-of-8 short-source gate passes and the US$20 engineering cap is not reached. |

Report median and p90 end-to-end wall time, peak memory, temporary and retained bytes, analyzed-window coverage, provider/GPU/CPU/transfer quantities, retry count, and usable outputs alongside gates. A quality or cost failure is evidence; do not adjust a threshold after seeing results. If fewer than seven candidates are selected because humans labeled fewer than seven usable moments, report that case as correctly sparse.

## Versioned interchange contracts

The contracts live in contracts/ and use JSON Schema draft 2020-12. The source metadata reference is ai-clip.source.v1. Every downstream object repeats source ID, exact-byte SHA-256, duration in milliseconds, timebase, and half-open interval semantics so stale or mismatched artifacts can be rejected. Transcripts preserve the source's original script and code-switching. Speaker identity may be missing or null. Word records use Unicode code-point character offsets into the exact original segment text, with nullable times for unaligned words; aligned times must fall within that segment. An immutable run-manifest hash links model, prompt, alignment, and parameter versions. Silence, non-speech audio, and visual-only evidence can be represented without invented dialogue. Candidates carry evidence references, rank and dedup versions, and five editorial score components. All candidate intervals are contiguous excerpts in original source order; generated speech and dialogue reordering are explicitly forbidden.

The local checker supports the JSON Schema keywords used by these checked-in schemas plus cross-artifact semantic checks; it is not a general JSON Schema implementation or a production ingestion validator. It does not compute the benchmark quality metrics or run ASR. Schemas and fixtures are checked using only Python's standard library. From the repository root, run **python3 tools/clipping/evaluation_validate.py --offline**. The fixture examples are synthetic contract examples; they are not real media, human labels, benchmark inputs, measurements, or quality evidence. Each source fixture uses C1.1's simulation wrapper with a true simulated marker outside the source metadata; its upload route, attestation state, and fake stream summaries are fictional values. The source hash is over a small adjacent text sentinel, explicitly marked as not media, only to exercise hash linkage offline.

# M3: full-source analysis and clip candidates

The current Clipping workflow imports one public YouTube video and lets a signed-in user request analysis from an opt-in Modal worker. Transcript, context, and heuristic candidates are persisted and shown read-only. The UI has no file upload, Drive/Dropbox, batch, budget, retention, candidate-editing, export/publishing, or invoice-reconciliation flow. Source retention is an automatic server policy, not a browser setting.

The worker is callable only after an operator separately deploys it and configures the three least-privilege Modal secrets and authenticated application Settings. No worker was deployed, no model weights were fetched, and no live inference or paid call was made during this implementation. The UI's readiness value means `configured, not live checked`; it does not prove that the endpoint, credentials, Modal account, model download, or billing are operational.

M1 feasibility and measured quality targets were waived before this work. The offline fixtures verify code paths and bounds; they are not real-media accuracy, language, latency, or cost measurements. M3's evaluation-dependent exit criteria therefore remain unmeasured.

## Operator setup

Use a dedicated Modal app and three least-privilege secrets for this analysis worker. The worker requires an immutable 40-character lowercase Hugging Face commit ID for `Systran/faster-whisper-large-v3`; it refuses the floating names `main` and `large-v3` as a repository revision. Verify the selected model snapshot's license and permitted use at that exact upstream commit before deploying. The configured model volume keeps the downloaded snapshot; the worker loads its local pinned path and records the commit and a SHA-256 digest over its files in each result.

Choose one new `FRAMEVAULT_PIPELINE_REVISION` for each worker, model, FFmpeg, or analysis-algorithm release. Set the same revision in both Modal secrets that need it and in the application Settings. A revision change forces a new source-analysis cache entry. Changing the Hugging Face model commit also requires changing the pipeline revision. The application cannot independently inspect the Modal worker's secret, so matching the two values is an operator deployment step.

Choose a new 64-character hexadecimal worker bearer and create the Modal secret without putting that value in shell history or process arguments. Modal opens the configured editor for the bearer after you press Enter:

```sh
modal secret create framevault-clipping-dispatch-api-secret \
  FRAMEVAULT_CLIPPING_WORKER_SHARED_SECRET=- \
  FRAMEVAULT_CALLBACK_ORIGIN=https://<public-framevault-host> \
  FRAMEVAULT_PIPELINE_REVISION=m3-2026-10-09-1 \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
modal secret create framevault-clipping-runtime-secret \
  FRAMEVAULT_CALLBACK_ORIGIN=https://<public-framevault-host> \
  FRAMEVAULT_PIPELINE_REVISION=m3-2026-10-09-1 \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
modal secret create framevault-clipping-model-prewarm-secret \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
```

When the editor opens for `FRAMEVAULT_CLIPPING_WORKER_SHARED_SECRET`, enter the bearer there. Keep it available only for entry into the signed-in dashboard Settings; do not paste it into a command or URL. The dispatch API secret is attached only to the authenticated dispatch function. The runtime secret is separate and omits the dispatch bearer; it is attached to ledger, analysis, and callback-replay functions. The prewarm secret contains only the model revision and is attached only to the CPU prewarm function. `required_keys` validates key presence; separate secret names provide the actual access separation.

Before enabling dispatch, separately authorize deployment and then run the CPU-only model prewarm once for the configured immutable model commit. This downloads model weights and can consume provider resources, so review the exact model license before authorizing that operation:

The Modal analysis function requests 524,288 MiB (512 GiB) of ephemeral disk, the minimum accepted by Modal's current 524,288–3,145,728 MiB range. This platform resource request is separate from the worker's 20 GiB source-file limit; it does not represent measured per-job scratch use or a quoted charge.

Modal stages the entry script at `/root`; every registered function image also mounts the sibling `clipping_analysis.py` and `clipping_protocol.py` files at that import location. Keep those source mounts on the API, ledger, callback replay, CPU prewarm, and GPU analysis images when changing the worker's image definitions.

```sh
modal deploy workers/modal/clipping_m3_worker.py
modal run workers/modal/clipping_m3_worker.py::app.clipping_model_prewarm_task
```

Prewarm uses an isolated CPU function, a hard time limit, and an atomic ready marker containing the expected revision and snapshot digest. The GPU analysis function fails closed unless that marker and local snapshot validate; it resolves the model with local files only and never initiates a model download. Re-run prewarm after changing the model revision or replacing the model volume. Prewarm and deployment were not run for this implementation.

Copy the exact public `/dispatch` URL printed by Modal. In the signed-in FrameVault dashboard, open **Clipping > Modal worker setup** and enter that URL, the same shared bearer secret, the same pipeline revision, and the maximum analysis time (1–43,200 seconds). Enable the worker only after comparing all values with the deployed Modal secret. The dispatch endpoint must be the exact HTTPS `*.modal.run/dispatch` host; FrameVault resolves and pins public DNS addresses for the request, verifies TLS, refuses redirects, and limits request, response, and transfer sizes. The browser does not configure a rate or application budget.

Set `FRAMEVAULT_CALLBACK_ORIGIN` to the public FrameVault origin, with HTTPS and no path. The worker accepts only media and callback paths matching the assigned job and attempt under that origin. Do not put bearer tokens or capabilities in URLs. The shared worker bearer is encrypted by FrameVault and omitted from configuration responses. Per-job media and callback capabilities are sent to the worker in protected headers, scoped to one attempt, and expire at the earlier of the stage lease plus 24 hours or source retention deadline. The worker downloads to a private temporary file, checks the full-source SHA-256, deletes the file after analysis, and applies `file,crypto,data` protocol plus `mov,matroska,webm` container allowlists to ffprobe, every FFmpeg scan, and PyAV transcription. A CPU-only ledger owner serializes all SQLite-volume operations, including replay-ledger retention pruning every 60 seconds; that volume is not mounted on the GPU analysis function. Modal volumes hold the model cache and idempotency ledger, not application media or the application SQLite database.

## Runtime behavior and result limits

The only runtime transcription model is faster-whisper `large-v3`, language detection is automatic, and transcript segments retain original-script text and source timestamps. The protocol accepts at most 20,000 transcript segments and fails closed above that bound. faster-whisper does not diarize, so speaker IDs are null. The worker analyzes full-source audio energy/silence and sampled visual scene/motion signals, builds extractive lexical context, and performs denser 2 fps visual inspection over a bounded, non-overlapping pool of transcript/audio/visual anchors. Profile cues are deterministic and heuristic; they do not establish semantic understanding. A source without an audio stream skips ASR and audio analysis, reports that status explicitly, and can still return low-confidence candidates grounded in visual measurements without inventing transcript text. Sources whose audio and video stream start times differ by more than 50 ms are rejected because this version does not normalize cross-stream timestamp offsets. The game profile uses measured motion/audio and nearby commentary cues; it does not detect faces or verify facecam presence. The workflow is bounded to four hours and 20 GiB per source, with a configurable worker compute-time limit of at most 12 hours. Worker source-core payloads are capped at 3 MiB under the 4 MiB stored-artifact limit. Analysis checks its deadline and source lease during media download, subprocess work, and analysis loops. faster-whisper model construction is synchronous, so cancellation may be delayed until initialization returns; Modal's function timeout is the hard outer bound.

Candidate editorial dimensions, confidence labels, hooks, and titles come from deterministic heuristics and measured signals. They are not calibrated probabilities, semantic video understanding, a viral prediction, or a guarantee of engagement. Audio transients are not confidently classified as laughter or other semantic events. Scene/motion analysis does not identify objects or actions. Hindi, Hinglish, Nepali, and mixed-language performance has not been benchmarked. Review every transcript and clip boundary before use.

The current browser and clipping API do not expose application budgets, rate estimates, invoice reconciliation, or batch accounting. Modal infrastructure costs are billed by Modal and are not estimated or reconciled by FrameVault; review provider billing separately. Analysis results are stored as read-only output.

Persisted analysis includes the source SHA-256, exact model commit and weight digest, runtime/algorithm versions, language metadata, transcript, context, events, and candidate results. Runtime provenance includes the installed Python distribution inventory, OS release, FFmpeg binary/configuration hashes, and a manifest hash. These values audit an executed worker; they do not make the Modal base image or apt-resolved FFmpeg build reproducible. Before deployment, freeze the base image, FFmpeg package, and transitive dependency set, then set a new `FRAMEVAULT_PIPELINE_REVISION` for that worker build. A different source hash or operator pipeline revision cannot reuse the same analysis cache entry. Source media and derived artifacts are cleaned up automatically according to server-side retention and lease rules; there is no user-facing retention setting.

Signed-in users can delete an imported source with `DELETE /api/clipping/sources/{id}` or remove one analysis with `DELETE /api/clipping/jobs/{id}`. Source deletion immediately tombstones the source, cancels its active import and analyses, hides their results, and prevents late callbacks from restoring them. When an importer is still unwinding, the API returns `202 {"cleanup_pending":true}` and removes any final late file write after that operation stops; otherwise it returns `204`. Analysis deletion preserves the job and attempt audit rows while hiding the result and canceling active work. A submitted worker callback capability remains usable only through its existing expiry window so a late response can settle without publishing; retry and new analysis remain blocked until the previous attempt settles or its callback window expires.

Go processor failures and valid current-attempt Modal failures transition the affected analysis to `failed` and publish a job update. The browser reports a generic toast for a live failure event and displays only the server's sanitized job error in the job detail. Setup and analysis/result-contract failures persist a bounded canonical failure envelope before attempting delivery. If a cached-result replay cannot be delivered, the worker sends the same failure envelope and retains the existing cache unless Go acknowledges it. Both paths retry callback delivery without repeating inference. Callback capabilities and attempt identity checks remain in force: unauthenticated, stale-attempt, stale-dispatch, or legacy-protocol callbacks are rejected without changing current work. The Modal ledger keeps its no-repeat inference record; acknowledged failure callbacks clear cached result content, and explicit retries are allowed after the previous attempt settles or its callback window expires.

## Dependency and evaluation limits

Worker-only direct runtime pins are isolated in [`requirements-clipping.txt`](../../workers/modal/requirements-clipping.txt); the existing Go production pins and images are unchanged. These direct pins do not yet lock transitive wheel hashes, the Modal Debian base image, or apt FFmpeg. Treat a reproducible worker build as a deployment blocker until those are pinned and reviewed; runtime fingerprints audit an executed build but do not pin it in advance. The pinned projects report these upstream licenses: Modal, Hugging Face Hub, and Tokenizers are Apache-2.0; FastAPI, faster-whisper, and CTranslate2 are MIT; PyAV and NumPy are BSD-3-Clause. Review transitive notices and the exact model snapshot's own license before a production deployment. The Modal SDK was installed only into a temporary local validation environment; no worker image, model weights, or deployment was downloaded or executed here.

Local deterministic tests cover protocol and storage bounds, original-script/full-timeline timestamps including late non-speech events, real FFmpeg analysis of generated fixtures (including rejected stream-start skew), model revision pinning and CPU prewarm with a mocked Hugging Face client, deadlines, finalist sequence inspection, source hash checks, replay/idempotency, stale callbacks, cache restart/reselection, revision invalidation, and automatic source retention. The browser regression suite covers the current YouTube-import and read-only-results workflow. These checks do not substitute for labeled real-media review or the waived M1 corpus and benchmark.

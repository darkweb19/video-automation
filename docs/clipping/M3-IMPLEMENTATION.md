# M3: full-source analysis and clip candidates

M3 adds an opt-in Modal analysis worker and a persisted, editable candidate-selection flow. The worker is callable only after an operator separately deploys it and configures the three least-privilege Modal secrets and authenticated application Settings. No worker was deployed, no model weights were fetched, and no live inference or paid call was made during this implementation. The UI's readiness value means `configured, not live checked`; it does not prove that the endpoint, credentials, Modal account, model download, or billing are operational.

M1 feasibility and measured quality targets were waived before this work. The offline fixtures verify code paths and bounds; they are not real-media accuracy, language, latency, or cost measurements. M3's evaluation-dependent exit criteria therefore remain unmeasured.

## Operator setup

Use a dedicated Modal app and three least-privilege secrets for this analysis worker. The worker requires an immutable 40-character lowercase Hugging Face commit ID for `Systran/faster-whisper-large-v3`; it refuses the floating names `main` and `large-v3` as a repository revision. Verify the selected model snapshot's license and permitted use at that exact upstream commit before deploying. The configured model volume keeps the downloaded snapshot; the worker loads its local pinned path and records the commit and a SHA-256 digest over its files in each result.

Choose one new `FRAMEVAULT_PIPELINE_REVISION` for each worker, model, FFmpeg, or analysis-algorithm release. Set the same revision in both Modal secrets that need it and in the application Settings. A revision change forces a new source-analysis cache entry; candidate-profile, duration, and count edits reselect from the existing core without re-running ASR. Changing the Hugging Face model commit also requires changing the pipeline revision. The application cannot independently inspect the Modal worker's secret, so matching the two values is an operator deployment step.

Choose a new 64-character hexadecimal worker bearer and create the Modal secret without putting that value in shell history or process arguments. Modal opens the configured editor for the bearer after you press Enter:

```sh
modal secret create framevault-clipping-dispatch-api-secret \
  FRAMEVAULT_CLIPPING_WORKER_SHARED_SECRET=- \
  FRAMEVAULT_CALLBACK_ORIGIN=https://<public-framevault-host> \
  FRAMEVAULT_PIPELINE_REVISION=m3-2026-10-09-1 \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
modal secret create framevault-clipping-runtime-secret \
  FRAMEVAULT_CALLBACK_ORIGIN=https://<public-framevault-host> \
  FRAMEVAULT_PIPELINE_REVISION=m3-2026-10-09-1 \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
modal secret create framevault-clipping-model-prewarm-secret \
  FRAMEVAULT_WHISPER_MODEL_REVISION=<40-character-lowercase-huggingface-commit>
```

When the editor opens for `FRAMEVAULT_CLIPPING_WORKER_SHARED_SECRET`, enter the bearer there. Keep it available only for entry into the signed-in dashboard Settings; do not paste it into a command or URL. The dispatch API secret is attached only to the authenticated dispatch function. The runtime secret is separate and omits the dispatch bearer; it is attached to ledger, analysis, and callback-replay functions. The prewarm secret contains only the model revision and is attached only to the CPU prewarm function. `required_keys` validates key presence; separate secret names provide the actual access separation.

Before enabling dispatch, separately authorize deployment and then run the CPU-only model prewarm once for the configured immutable model commit. This downloads model weights and can consume provider resources, so review the exact model license before authorizing that operation:

The Modal analysis function requests 524,288 MiB (512 GiB) of ephemeral disk, the minimum accepted by Modal's current 524,288–3,145,728 MiB range. This platform resource request is separate from the worker's 20 GiB source-file limit; it does not represent measured per-job scratch use or a quoted charge.

Modal stages the entry script at `/root`; every registered function image also mounts the sibling `clipping_analysis.py` and `clipping_protocol.py` files at that import location. Keep those source mounts on the API, ledger, callback replay, CPU prewarm, and GPU analysis images when changing the worker's image definitions.

```sh
modal deploy workers/modal/clipping_m3_worker.py
modal run workers/modal/clipping_m3_worker.py::app.clipping_model_prewarm_task
```

Prewarm uses an isolated CPU function, a hard time limit, and an atomic ready marker containing the expected revision and snapshot digest. The GPU analysis function fails closed unless that marker and local snapshot validate; it resolves the model with local files only and never initiates a model download. Re-run prewarm after changing the model revision or replacing the model volume. Prewarm and deployment were not run for this implementation.

Copy the exact public `/dispatch` URL printed by Modal. In the signed-in FrameVault dashboard, open **Clipping > More settings > Analysis worker setup** and enter that URL, the same shared bearer secret, the same pipeline revision, and an operator-declared rate in integer microUSD per maximum worker second. Enable the worker only after comparing all values with the deployed Modal secret. The dispatch endpoint must be the exact HTTPS `*.modal.run/dispatch` host; FrameVault resolves and pins public DNS addresses for the request, verifies TLS, refuses redirects, and limits request, response, and transfer sizes.

Set `FRAMEVAULT_CALLBACK_ORIGIN` to the public FrameVault origin, with HTTPS and no path. The worker accepts only media and callback paths matching the assigned job and attempt under that origin. Do not put bearer tokens or capabilities in URLs. The shared worker bearer is encrypted by FrameVault and omitted from configuration responses. Per-job media and callback capabilities are sent to the worker in protected headers, scoped to one attempt, and expire at the earlier of the stage lease plus 24 hours or source retention deadline. The worker downloads to a private temporary file, checks the full-source SHA-256, deletes the file after analysis, and applies `file,crypto,data` protocol plus `mov,matroska,webm` container allowlists to ffprobe, every FFmpeg scan, and PyAV transcription. A CPU-only ledger owner serializes all SQLite-volume operations, including replay-ledger retention pruning every 60 seconds; that volume is not mounted on the GPU analysis function. Modal volumes hold the model cache and idempotency ledger, not application media or the application SQLite database.

## Runtime and accounting

The only runtime transcription model is faster-whisper `large-v3`, language detection is automatic, and transcript segments retain original-script text and source timestamps. The protocol accepts at most 20,000 transcript segments, and fails closed above that bound. faster-whisper does not diarize, so speaker IDs are null. The worker analyzes full-source audio energy/silence and sampled visual scene/motion signals, builds extractive lexical context, and performs denser 2 fps visual inspection over a bounded, non-overlapping pool of transcript/audio/visual anchors. The pool reserves an inspection for each supported profile when that profile has measurable cues, so profile edits can reselect from the cached core without another ASR run. Profile cues are deterministic and heuristic; they do not establish semantic understanding. A source without an audio stream skips ASR and audio analysis, reports that status explicitly, and can still return low-confidence candidates grounded in visual measurements without inventing transcript text. Sources whose audio and video stream start times differ by more than 50 ms are rejected because this version does not normalize cross-stream timestamp offsets. The game profile uses measured motion/audio and nearby commentary cues; it does not detect faces or verify facecam presence. It stops at the four-hour, 20 GiB, and 12-hour compute bounds; worker source-core payloads are capped at 3 MiB to reserve room for Go's selection enrichment under the 4 MiB stored-artifact limit. Cancellation and lease/retention expiry are checked during media download, subprocess work, and analysis loops. faster-whisper model construction is synchronous, so cancellation may be delayed until initialization returns; Modal's function timeout is the hard outer bound.

Candidate editorial dimensions, confidence labels, hooks, and titles come from deterministic heuristics and measured signals. They are not calibrated probabilities, semantic video understanding, a viral prediction, or a guarantee of engagement. Audio transients are not confidently classified as laughter or other semantic events. Scene/motion analysis does not identify objects or actions. Hindi, Hinglish, Nepali, and mixed-language performance has not been benchmarked. Review every transcript and clip boundary before use.

Before dispatch, FrameVault reserves a bounded amount from both job and batch budgets using the operator-declared per-second estimate and maximum compute time. This is not a Modal quote or settled charge; Modal charges may include GPU, startup, storage, and transfer costs not represented by that estimate. The attempt reservation remains outstanding until an operator records an invoice amount and reconciliation reference, including an explicit zero. If a callback is late or missing, the job is not retried automatically. Retry remains blocked until invoice reconciliation and callback expiry, and an unresolved attempt for the same source also blocks dispatch under a newer pipeline revision; changing the revision invalidates cache reuse but does not release an uncertain cost. A late authenticated result may settle the invoice without reviving a canceled job or publishing its artifact.

The analysis core is persisted with source SHA-256, exact model commit and weight digest, runtime/algorithm versions, language metadata, full transcript, context, events, finalist inspections, and source-retention expiry. Runtime provenance includes the sorted installed Python distribution inventory, OS release, FFmpeg binary/configuration hashes, and a manifest hash. These values audit an executed worker; they do not make the Modal base image or apt-resolved FFmpeg build reproducible. Before deployment, freeze the base image, FFmpeg package, and transitive dependency set, then set a new `FRAMEVAULT_PIPELINE_REVISION` for that worker build. Changing the editorial content profile or allowed clip duration/count reuses the cached core and creates a new bounded selection. A different source hash or operator pipeline revision cannot reuse it. Retention tombstones remove media, transcript-bearing cache/artifacts, and in-flight analysis claims while preserving the soft source row and job/stage/attempt accounting audit. A terminal job may be tombstoned once its media lease allows it; the encrypted callback/lease capabilities and expiry index remain until their recorded callback window closes, so a late authenticated callback can settle cost without publishing analysis. Nonterminal jobs, including `paused_budget`, retain their source until every callback window expires; the independent media-lease guard still applies.

## Dependency and evaluation limits

Worker-only direct runtime pins are isolated in [`requirements-clipping.txt`](../../workers/modal/requirements-clipping.txt); the existing Go production pins and images are unchanged. These direct pins do not yet lock transitive wheel hashes, the Modal Debian base image, or apt FFmpeg. Treat a reproducible worker build as a deployment blocker until those are pinned and reviewed; runtime fingerprints audit an executed build but do not pin it in advance. The pinned projects report these upstream licenses: Modal, Hugging Face Hub, and Tokenizers are Apache-2.0; FastAPI, faster-whisper, and CTranslate2 are MIT; PyAV and NumPy are BSD-3-Clause. Review transitive notices and the exact model snapshot's own license before a production deployment. The Modal SDK was installed only into a temporary local validation environment; no worker image, model weights, or deployment was downloaded or executed here.

Local deterministic tests cover protocol and storage bounds, original-script/full-timeline timestamps including late non-speech events, real FFmpeg analysis of generated fixtures (including rejected stream-start skew), model revision pinning and CPU prewarm with a mocked Hugging Face client, cancellation/deadlines, finalist sequence inspection, source hash checks, replay/idempotency, stale callbacks, cache restart/reselection, revision invalidation, source retention, and explicit invoice reconciliation. These checks do not substitute for labeled real-media review or the waived M1 corpus and benchmark.

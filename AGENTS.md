# Project context and invariants

- This is a Go HTTP server with an embedded dashboard. Keep browser code in `static/` and preserve same-origin authenticated APIs.
- Video providers implement `VideoService`; selection and account configuration live in persisted SQLite settings. Story/script generation stays on the fixed OpenRouter `ScriptModel`; provider-specific video request handling belongs inside provider clients.
- Random prompt generation supports `project` and `single` modes. It shuffles five explicit `:free` OpenRouter text variants, with 12 seconds per attempt and a 70-second total deadline. Never add a paid fallback. Authentication and invalid-request failures stop immediately; only transient, unavailable, or unusable responses rotate to another free model. Keep this rotation separate from the fixed story planner. Check the current [OpenRouter free-model catalog](https://openrouter.ai/collections/free-models/) and [free-tier limits](https://openrouter.ai/docs/api_reference/limits) before changing model IDs.
- The fixed project preset is five six-second scenes at 480p/9:16. Model capabilities are runtime data: populate/consume `VideoModel` duration, resolution, aspect ratio, audio, and pricing fields; reject incompatible models clearly.
- New Modal single/project submissions use a Go-assigned `gen_<32 hex>` ID and persist the job before dispatch. Set `VIDEO_CALLBACK_BASE_URL` on the Go process/container to a public HTTPS origin; it is optional at startup and for OpenRouter, but required for Modal submission. Go appends `/api/video-callbacks/{id}`.
- Modal workers are `modal/video.py` (Wan 2.2) and `workers/modal/skyreels.py` (SkyReels V2). New callback jobs use the shared Modal Dict `video-generation-job-claims` for atomic request/GPU claims and immutable call IDs; workers also mirror GPU call IDs to their jobs volume, without callback credentials. Per-job 32-byte bearer tokens are stored encrypted plus SHA-256 hash in SQLite, never returned to the browser, job JSON, or logs.
- Callback protocol: processing sequence 1, terminal completed/failed sequence 2. Workers persist terminal results before delivery, use four HTTP attempts (5-second timeout, no redirects), and Modal supervisor retries (240, exponential 1–60-second delay) re-send the saved result without another GPU run. Keep ambiguous Modal spawn acknowledgments pending; same-ID retries must not dispatch duplicate GPU work. Go applies monotonic updates, downloads completed MP4s locally, and combines projects locally. New callback jobs do not poll Modal; preserve polling for legacy and OpenRouter jobs. Missing callbacks fail visibly after eight hours.
- Local MP4 downloads are capped at five attempts. Persist the terminal single-job or scene error and project roll-up; failed scenes can be retried without regenerating successful scenes.
- API credentials and callback tokens must be encrypted at rest and never returned to the browser. Settings may expose configured booleans and non-secret configuration only. Never log credentials or read/print `.env` contents.
- Persistent application data lives in SQLite and the configured data directory/Docker volume. Storage migrations must remain restart-safe and preserve existing records.
- Keep provider/text generation calls mocked in routine tests; never run paid generation. Useful checks: `go test ./...`, `node --check static/app.js`, `node --test tests/dashboard-ui.test.cjs`, `python modal/test_video_callbacks.py`, `python workers/modal/test_skyreels.py`, and `git diff --check`.
